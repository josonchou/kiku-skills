# 绩效总结证据矩阵

| KPI 项目 | Git 可直接佐证 | 需外部系统或用户补充 | 建议写法 |
|---|---|---|---|
| 研发效率 | 功能交付主题、跨项目联动、修复与重构、分支合并、持续活跃 | 工时评估、提测时效、日报完成率、逾期数量、AI 使用时长 | 先写交付范围与闭环能力；量化阈值无数据时写“需补充项目管理数据”。 |
| 协同效率 | 多仓库改动、接口适配、跨端对齐、联调修复、合并记录 | 干系人反馈、响应时效、投诉记录 | 写清协同对象、边界和解决的问题，不用 merge 数量代替协同质量。 |
| 知识沉淀 | 设计文档、OpenSpec、README、skills、脚本、迁移说明 | 方案评审记录、组内文档目录、实际复用反馈 | 说明沉淀物、覆盖场景和后续复用价值。 |
| 交付质量 | 验收/测试相关提交、表单校验、错误处理、兼容修复 | 冒烟报告、测试打回记录、发布验收单 | 写已完成的核心链路和验收修复；不要无证据宣称“零打回”。 |
| 质量提升 | 安全校验、并发锁、错误兜底、空安全、性能与体验修复 | 内网缺陷时效、线上故障等级、用户反馈、监控指标 | 写问题类型、治理手段和风险降低；故障数量以缺陷系统为准。 |
| 技术创新 | 新技术实现、跨端适配、工程化流程、可复用平台能力 | 技术评审、成本/质量/效率收益、AI 提效比 | 写技术决策和解决的业务问题，补充可量化收益时再写结论。 |
| 资源节省 | 按需加载、资源压缩、缓存、请求去重、渲染优化 | 资源体积、接口量、CDN 成本、性能前后指标 | 写优化动作和减少的无效开销；成本收益没有监控数据时保持定性。 |

## Git 归集建议

1. 使用 author email 作为主身份；同邮箱的 author name 变体一并纳入。
2. 指定日期边界和本地时区；排除 stash 与未提交变更。
3. 统计 branches、remotes、tags 中可达提交，并对 commit SHA 去重。
4. 对高价值主题查看具体变更文件，避免把宽泛 commit message 当作完成证明。
5. 提交数和变更行数仅作为内部线索；报告正文优先呈现交付内容和价值。
