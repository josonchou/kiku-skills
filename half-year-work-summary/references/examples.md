# 使用示例

## 从工作区生成半年总结

**输入：**

> 分析当前目录下我 2026 年上半年的提交，按研发效率、质量保障、创新应用和成本节省写一份 KPI 总结，重点写工作内容，不要只统计提交数。

**预期行为：** 识别 Git 项目和身份，归集周期内可达提交，按重点工作流整理；将日报、逾期、故障等级等无法从 Git 验证的指标标为待补数据。

## 未提供工作区路径

**输入：**

> 帮我根据上半年提交写 KPI 自评。

**预期行为：** 先询问“需要扫描哪个工作区？请提供包含 Git 项目的项目目录路径。”；在用户提供路径前，不扫描当前目录、Home 目录或按目录名猜测项目范围。

## 按 KPI 截图更新飞书文档

**输入：**

> 按这张绩效表的五列格式，把上半年的总结写入我的飞书私人空间；完成情况沿用已确认的工作内容，不要改成提交统计。

**预期行为：** 提取五列结构；使用飞书用户身份写入 `my_library`；完成情况以业务交付、协同、质量治理和知识沉淀为核心；写后 fetch 核验并返回链接。

## 只调整表格样式

**输入：**

> KPI 内容不要动，改成截图里的五列表格；表格显得单调，帮我润色完成情况。

**预期行为：** 读取现有飞书文档和表格 block；保留已确认的事实；将完成情况润色为“工作主题、解决的问题、沉淀/价值”的短段落；仅替换目标表格，不覆盖整篇文档。
